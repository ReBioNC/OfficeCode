# Privacy and local storage

OfficeCode listens only on `127.0.0.1`. The global plugin mirrors OpenCode session metadata, including titles, agent roles, parent session IDs, tool names and call IDs, activity targets, completion status, and permission waits, to the local dashboard. Project data and activity logs are stored under `%LOCALAPPDATA%\OfficeCode\projects\` on Windows or `~/.local/share/OfficeCode/projects/` on macOS/Linux. Session titles and tool metadata may contain sensitive information; review them before sharing.

Detailed workflow timelines and concurrent tool lists are held in server memory. Each run's timeline keeps its latest 100 entries; it is not restored after the server stops. Existing event ledgers and transcripts remain on disk. The dashboard does not copy model reasoning or tool output into its new timeline.

The browser does not store API keys or call model providers. In plugin mode, the connected agent app selects and runs every model; standalone dispatch is disabled. Avatar rendering, navigation, role labels, connection checks, and themes make no model calls. Other local processes can access the HTTP server while it is running; do not expose its port to a public network.

The native Hermes adapter forwards bounded task text, role/session relationships, activity labels, filenames without parent paths, tool IDs, timing, and outcomes. It does not forward raw shell arguments, file contents, search queries, provider requests/responses, tool results, model reasoning, or credentials. Hermes sessions are namespaced and their data uses the same local project registry, keyed by the profile directory or explicitly selected shared studio. Actual OpenCode workspaces and original agent names appear in the inspector; Hermes task workspace stays unknown when not reported by Hermes. Hooks return `None` and do not change tool/approval decisions. The connector writes to a background pipe, preserving completion boundaries while coalescing adjacent activity updates.

The Hermes installer adds a managed MCP startup/status entry, preserving other configuration values and backing up config.yaml. This entry starts a local server before a task without calling a model. The separate native `officecode_delegate_opencode` tool explicitly runs real OpenCode work in a selected directory, with OpenCode's model and permissions. Its bounded assistant result returns to Hermes; raw reasoning/tool output/diagnostics are excluded from dashboard telemetry. Delegation can read/change project files according to OpenCode's configured permissions and consumes OpenCode tokens. Tool definitions add context in Hermes. Disabling the observer does not disable the MCP startup entry; remove both to turn off the integration completely.

Manual development mode (`npm run dev`) is separate. It stores state in `<workspace>/.officecode/` and run results in `<workspace>/output/outbox/`. The mock driver makes no model calls. Without the mock driver, the development run API can invoke the OpenCode CLI with the user's OpenCode provider configuration.
